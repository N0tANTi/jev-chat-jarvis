# Jev 桌面试用版

Windows 10/11，Python 3.11+（含 Tk），Pillow。使用已有 Jev 题目集，独立于 Android 构建。

```powershell
python -m pip install -r desktop/requirements.txt
python -m desktop.app --env-file "本机已有的.env路径"
```

在仓库根目录执行。也可双击 `desktop/Start.cmd`，默认读取 `desktop/.env`。
只需要三个变量：`MINERU_API_TOKEN`、`DEEPSEEK_API_KEY`、`TYPESAFE_API_KEY`。
进程环境优先；密钥不显示在界面，不写入日志。用户授权的本地 `.env` 被 Git 忽略。

1. 打开微信单聊，点击「截取聊天」，拖动框选消息气泡；Esc 取消。也可导入截图。
2. 在预览中检查范围，再点击「识别聊天」。所选截图上传 MinerU 云端，等待异步 OCR。
3. 核对发言人和顺序，删除标题、时间及系统提示。每条一行，格式 `我：内容` / `对方：内容`。
4. 勾选核对完成，点击「生成回复」。DeepSeek `deepseek-flash` 非思考模式生成三条，TypeSafe Jev `jev-latest` 判断排序。
5. 点击「复制」，回微信确认当前联系人，自行粘贴发送。切换聊天后重新截图。

可以不使用 OCR：直接在文字框粘贴上述格式的聊天，勾选核对后生成。
本地快捷启动文件 `start-local.cmd` 可引用现有 env 路径，属于忽略项，不上传。

## 直接读取试用（免 OCR，发言人仍需核对）

本机兼容启动后，标准 UIA 已能看到消息正文；尚未确认可靠的发言人属性。
此入口不是原生全自动回复，也不是后台全微信监听。

1. 保持当前兼容启动的微信运行；双击一个好友会话，打开独立单聊窗口。
2. 关闭旧助手并用原 `start-local.cmd` 重开。其他机器先安装更新的 requirements。
3. 选好好友档案，点击「直接读取微信（免 OCR）」并选择对应窗口。群聊暂不接受。
4. 每约 1.5 秒发起一次本地读取，最多显示控件当前提供的最后 30 条；不滚动加载历史。
   不截图、不调用 MinerU、不自动上传。独立窗口关闭、身份变化或读取失败会停止。
5. 把每条「待确认：」改为「我：」或「对方：」，删除系统、图片、语音等非正文项目。
   一开始编辑就停止更新，防止覆盖修改。勾选核对后，沿用原生成、角色、记忆和复制流程。

尚不能自动区分发送者或保证非文字消息完整，多行正文会合为一行供核对。
停止后是静态快照，不继续跟踪新消息；要刷新请再次点击读取并重新核对。
首次列表查询及每次读取最多等待 12 秒，超时仅结束读取子进程，不结束微信。
撤销/清空/切换档案会废弃迟到结果；不会保存窗口身份或聊天到日志，不会自动恢复监听。
目前通过合成测试和标准工具正文观察，产品适配器的真实单聊端到端仍待用户试用。
回退直接使用原截图入口。微信兼容启动及回退见[诊断手册](../docs/runbooks/wxauto-diagnostics.md)。

## 数据边界与限制

- 启动不截屏、不调用 API。不接管微信、不自动发送、不读聊天数据库、不做 MCP 伪接入。
- 截图与候选只在本次进程内存中保留；复制内容会留在系统剪贴板。
  你主动保存的好友档案、导入历史，以及开启学习后核对的聊天会保存在本机。
- 截图发送 MinerU；手动核对的文字或显式开启自动模式后的 OCR 文字、关系及档案上下文发送 DeepSeek / TypeSafe。云端留存由各服务政策决定。
- 关闭或清空会取消本地后续处理并忽略迟到结果；已经提交的云端任务无法撤回。
- 首版只适用于可见的单聊消息。裁剪范围由人选择；标题/通知/时间也可能被当成消息，必须核对。
- 用绿底辅助识别「我」，左侧辅助识别「对方」；歧义标记为「待确认」。深色主题、群聊、图片、引用、多行气泡可能误判或漏识别。
- 仅依据截图快照提供建议。自动模式检测选定区域的画面变化，没有消息 ID 或可靠的联系人 ID。
- MinerU 是异步文档 OCR，可能排队；轮询最多两分钟，单个网络请求另有超时。网络调用使用直接 HTTPS，不读取代理环境变量。
- 仅合成数据通过不代表真实微信适配已经完成；多屏缩放与真实聊天仍需试用反馈。

## 自动更新试用（无需 Plus）

1. 重启程序。若使用好友档案，先选好档案，并确认微信当前单聊就是这个人。
2. 打开微信，点击「截取聊天」，框选消息区，不含输入框、标题和联系人列表。
3. 点击「自动更新（云端）」，再框选消息区上方的**联系人标题文字**，避开动态图标。
4. 回到微信并保持前台、位置不变且不被其他窗口遮挡。初次及画面变化稳定后，
   自动上传裁剪图到 MinerU；最后一句识别为对方时自动生成三条回复。
5. 建议完成后切回助手查看、核对并复制；仍由你自己粘贴发送。
   「停止自动更新」、编辑文字、清空、切换档案或退出都会停止采集。

每 750 毫秒本地检查一次，等待画面稳定 1.5 秒，提交间隔至少 5 秒；同一画面不重复处理。
这不是固定延迟承诺：云端 OCR 可能排队；滚动消息、动画、鼠标悬停变化也可能触发重新识别。
进入后台或检测到遮挡时暂停，未完成任务作废；回到微信可重新识别。
检测到标题变化、窗口移动/缩放、OCR 错误时停止，需重新绑定。已上传请求无法撤回。

标题只在本地比对像素，不上传。它不是微信联系人 ID：同名会话、短暂切换、部分遮挡可能漏检；
标题动态变化也可能误停。遮挡检查采用区域采样，不能保证识别所有覆盖物。请只在已确认的
一个单聊中试用，切换好友先停止；本版不承诺全微信后台监听或群聊支持。

自动建议可以使用已有角色/好友记忆，但**未经核对的自动 OCR 不写入长期历史或标签**。
需要学习本次内容时，停止自动模式，核对文字并勾选，然后手动生成（需已开启该好友的学习）。
没有引入 wxauto 源码或绕过 Plus 授权，也没有注册包含发送工具的 MCP。
回退：停止自动更新后使用原有手动截图流程，不需卸载组件或调整微信版本。

## 角色、好友档案和迭代记忆

关闭旧程序后重新启动，点击「角色 / 好友记忆」。

1. 在「我的角色」填写你希望的说话方式，可直接保存，全局生效。例：简短直接、温和但不讨好、少用表情、不替我作承诺。
2. 新建好友档案，在「已确认背景」填写关系、已知事实、沟通边界。不同好友使用独立 ID，同名也不合并。
3. 在「导入历史」粘贴或导入 UTF-8 文本，每条一行 `我：…` / `对方：…`，导入只保存本机。
4. 点击「分析已保存历史」，将该好友最近最多 200 条 / 3 万字历史发送 DeepSeek；观察附带消息依据、模型把握和更新时间。
5. 点击「使用此好友」，主界面生成回复时使用你的角色、该好友确认背景、最近最多 20 条 / 6000 字历史和当前模型观察，分别发送给 DeepSeek 和 TypeSafe。
6. 可选开启「生成回复后保存核对的聊天，并在有新内容时更新模型观察」。回复先显示，随后后台更新标签；这是根据你核对的内容迭代，**不是全微信实时监听**。

档案位置：`%LOCALAPPDATA%/JevDesktop/profiles.json`（本机明文 JSON）。首次显式保存才创建，
不进入 GitHub。每好友最多保留 500 条 / 10 万字历史、当前观察和三版旧观察，超限裁掉最早历史。
「清除好友记忆」删除该好友历史和观察、关闭学习，保留手工背景；「清除观察并停学」保留历史。
关闭窗口不删除已保存的档案。切换好友会清空当前聊天、临时关系描述和候选，需重新选取当前聊天。

模型观察始终是推测，不覆盖手工确认的事实；不会主动推断健康、政治、宗教等敏感属性。
新消息可以修正旧观察。上下文用于帮助措辞和回忆，不能保证提高所有场景的回复质量。
重叠快照按文本序列去重，缺少真实消息 ID 时无法完全区分重复发送与重复截图；记录时间是导入时间。

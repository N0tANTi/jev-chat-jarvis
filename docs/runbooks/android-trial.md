# 微信试用：会话安全修复版

本 fork 的修改在 `codex/session-safety-fixes` 分支。仓库原有 `apk/` 文件是上游旧版，
**不包含本次修复**。请使用 Android trial 工作流对应提交的构建产物。

本次验收产物：[代码提交 6f13c06 的构建](https://github.com/N0tANTi/jev-chat-jarvis/actions/runs/35697258673)，
下载 `jev-session-fix-trial` 并解压其中的 APK。SHA-256 见 [当前状态](../../CURRENT_STATE.md)。

## 安装与配置

1. Android 11+、arm64 手机安装构建产物中的 `app-debug.apk`，桌面名称为
   **Jev 修复试用版**，包名 `com.jev.probe.trial`。可与原版并存，不会覆盖原版配置。
2. 如果装了原版，先关闭原版无障碍服务，避免两个悬浮窗同时读写。
3. 在试用版设置中，判断接口选择 **TypeSafe 直连**：
   地址 `https://api.typesafe.ai`，模型 `jev-latest`；密钥在手机设置中填写。
4. Jev 只负责判断和排序。生成回复需另配文字模型，例如 DeepSeek 官方
   `https://api.deepseek.com/v1` / `deepseek-flash`（DeepSeek V4.1 Flash），或 OpenRouter。
   不同服务商要分别填各自的密钥。未配置回复接口时仍可测试判断。
   本 fork 首次安装默认选中 TypeSafe + DeepSeek V4.1 Flash，只需填写两把密钥。
   回复使用非思考模式以减少等待，参数依据 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。
5. 开启试用版无障碍、悬浮窗权限。根据手机系统开启自启动和省电无限制。
   新安装的 APK 若受 Android 限制，先在系统应用信息中允许受限设置，再开启无障碍。
6. 初次测试建议关闭自动分析，先限定一个测试联系人，手动点“分析当前对话”。
   这是读取当前屏幕的辅助工具，无需登录或绑定微信账号。

APK、CI、Git 中均不包含个人 API 密钥。离线 OCR 在手机处理图片；判断和生成时，
当前消息及命中的背景/历史会发送到配置的模型接口。聊天历史默认不记录。

## 重点验收

| 场景 | 预期 |
|---|---|
| A 会话开始分析，立即切到 B | A 的结果不能覆盖 B；旧“填入”操作失效 |
| 分析期间连续收到两条新消息 | 当前任务完成后处理最新一屏，不丢失待分析消息 |
| 两个联系人都只有相同的“你好” | 仍按不同会话处理 |
| 输入框已有自己的草稿 | 保留草稿，候选只复制到剪贴板 |
| 点填入后马上切换会话 | 延迟重试停止，不能继续向新会话粘贴 |
| 切到微信会话列表或关闭功能 | 旧结果失效，不能重新弹出旧回复 |
| OCR 后切换聊天 | 过期 OCR 结果丢弃；OCR 模式候选仅复制，不自动填入 |
| 未配置文字模型 | 判断仍可显示；回复区域明确提示需要对应服务商密钥 |

发送按钮仍需自己点击。无障碍节点并不提供稳定的联系人唯一 ID：同名且同屏内容完全
相同的会话、目标 App 改版、群聊归属等仍需要真机检验。此版未修复所有机型兼容问题。

## 反馈与回退

反馈提供手机型号、Android/系统版本、微信版本、操作步骤、发生频率，以及脱敏后的
错误提示。不要提交真实聊天、API 密钥或完整系统日志。

回退只需关闭试用版无障碍服务和悬浮窗权限，重新打开原版服务；也可卸载试用版。
卸载会删除试用版自己的配置和历史，不影响微信数据或原版应用。

## 重新构建

在 JDK 17 + Android SDK 35 环境：

```sh
bash gradlew testDebugUnitTest assembleDebug lintDebug --no-daemon
```

也可在 fork 的 Android trial 工作流选择修复分支运行。CI 产物保留 14 天，包含 APK、
单元测试报告和 lint 报告；下载后核对对应提交。Debug 签名用于试用，CI 重建可能使用
不同的调试签名，后续覆盖安装如提示签名不一致，应先备好自己的配置再卸载试用版。
